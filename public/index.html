Real login

  • A JWT is three base64url parts joined by dots: header.payload.signature
  • Header: which algorithm signed it, HS256 here
  • Payload: the claims, like username, role, iat and exp
  • Signature: HMAC-SHA256 of header.payload, keyed with the server's secret
  • Header and payload are encoded, not encrypted. Anyone can read them
  • The signature is the only thing stopping someone from editing them
  • No token at all gets 401 on both servers

1.alg none

  • The token's header says which algorithm to check it with
  • The vulnerable server believes it. alg: "none" means skip the signature check
  • Attack: set alg to none, change role to admin, leave the signature empty
  • No secret needed
  • Fix: the server picks the algorithm, not the token. Only HS256 is accepted
src/server/vulnerable.tsrunning
// The header is attacker-controlled.
if (header.alg === "none") {
    return userFromClaims(payload.username, payload.role);
}
src/server/fixed.tsrunning
jwt.verify(token, FIXED_SECRET, {
    algorithms: ["HS256"],
})

2.Weak secret

  • HS256 signature: HMAC-SHA256 of header.payload with the secret
  • One real token gives you header.payload and the signature to check guesses against
  • Guessing happens offline. The server never sees the attempts
  • secret123 is in our 9 word list, so it falls on guess 7
  • With the secret you can sign any payload, like role: "admin"
  • Fix: a random 256-bit secret. Nothing to guess, and it isn't in the source code
  • The wordlist is our own, not a leaked password list
src/server/vulnerable.tsrunning
const VULNERABLE_SECRET = "secret123";
src/server/fixed.tsrunning
// A new random 256-bit secret on every start.
const FIXED_SECRET = randomBytes(32).toString("hex");

3.No expiry

  • exp is a Unix timestamp in seconds. Past it, the token should stop working
  • The vulnerable server passes ignoreExpiration: true, so exp is never checked
  • A stolen token works forever
  • Test: log in with a 1 second lifetime, use it, wait for exp to pass, use it again
  • Fix: let jsonwebtoken check exp. It does by default
src/server/vulnerable.tsrunning
jwt.verify(token, VULNERABLE_SECRET, {
    ignoreExpiration: true,
})
src/server/fixed.tsrunning
// jsonwebtoken checks exp by default.
jwt.verify(token, FIXED_SECRET, {
    algorithms: ["HS256"],
})
